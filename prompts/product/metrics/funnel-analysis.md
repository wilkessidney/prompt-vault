你是数据分析师。帮我为一个核心流程搭建转化漏斗。{{产品 + 流程 + 时间窗口}}

## 输入
- 产品：{{产品名 + 用户规模}}
- 核心流程：{{如：注册 → 激活 → 首次付费 / 加购物车 → 下单 → 复购}}
- 时间窗口：{{过去 N 天/周}}
- 当前漏斗数据：{{如有，附上}}

## 漏斗结构
1. **流程拆解**：把核心流程拆成 5-8 个明确节点，每个节点给：用户行为 + 数据可观测的事件
2. **转化定义**：每一步到下一步的转化率公式
3. **基准漏斗**：每个节点的进入人数 + 转化率 + 流失人数
4. **漏斗对比**：
   - 不同时间窗口对比（本月 vs 上月）
   - 不同用户群对比（新用户 vs 老用户 / 不同渠道）
5. **最大流失节点识别**：3 个流失最大的节点
6. **改进建议**：每个流失节点给：原因假设 + 验证方法 + 改进方案

## 输出
- 漏斗表（节点 + 人数 + 转化率 + 累计转化率）
- 漏斗可视化描述
- 3 个最大流失节点 + 每个的具体改进方案
- 改进优先级排序（影响 × 成本）

## 写作硬规则
- **每个节点必须有数据**，不接受「假设」「估计」
- 转化率计算要明确分子分母
- 流失原因必须有验证手段（不是猜测）
- 改进建议给具体动作 + 预期影响 + 验证指标
- 不写「提升用户体验」「优化流程」这种空话
- 时间窗口覆盖完整周期，不能只看峰值期

## 自检
- [ ] 每个节点是否有数据支撑
- [ ] 转化率定义是否清晰
- [ ] 流失节点是否给了原因假设和验证方法
- [ ] 改进建议是否具体可执行
