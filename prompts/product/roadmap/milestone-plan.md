你是项目管理顾问。帮我做一份里程碑计划。{{项目 + 时间窗口 + 关键节点}}

## 输入
- 项目名：{{产品 / 功能 / 平台}}
- 起始日期 + 截止日期：{{具体日期}}
- 团队：{{角色 + 配置}}
- 关键节点：{{已知 / 待定义}}

## 里程碑计划结构
### 1. 项目总览
- 项目愿景：≤50 字
- 成功标准：可验证的最终交付
- 关键干系人：发起人 / 决策者 / 影响者

### 2. 里程碑列表（5-10 个）
每个里程碑给：
- 里程碑名：{{简洁、动词开头}}
- 日期：{{具体日期，不写「月底」「下季度」}}
- 可交付物：{{明确的、可触摸的产出}}
- 判定标准：{{怎么判断里程碑达成}}
- 负责人：{{姓名}}
- 依赖：{{需要谁 / 什么先完成}}
- 风险：{{已知风险 + 缓解}}

### 3. 时间线
```
M1 (日期) ── M2 (日期) ── M3 (日期) ── M4 (日期) ── M5 (日期)
[启动]    [架构]      [开发]      [灰度]      [全量]
```

### 4. 风险与应急
- 风险清单：每个风险给：概率 + 影响 + 缓解 + 应急
- 关键路径：识别阻塞其他里程碑的关键节点
- 应急方案：每个里程碑失败的应对
- 调整机制：什么情况下调整里程碑

### 5. 沟通计划
- 例会：周 / 双周
- 评审：每个里程碑结束
- 升级机制：出现什么问题升级到谁
- 状态报告：每周发给谁的什么内容

## 写作硬规则
- **每个里程碑有明确日期**，不写「尽快」「月底」
- **每个里程碑有可触摸的可交付物**，不写「完成 XX 模块」
- 判定标准可验证，避免「差不多了就上」
- 风险给缓解方案，不只是列出
- 关键路径明确，避免「全都重要」
- 调整机制提前约定，避免临时大改

## 自检
- [ ] 每个里程碑是否有具体日期
- [ ] 可交付物是否可触摸
- [ ] 判定标准是否可验证
- [ ] 风险是否有缓解方案
- [ ] 调整机制是否清晰
