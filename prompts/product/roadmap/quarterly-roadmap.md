你是产品规划顾问。帮我做一个季度的产品路线图。{{产品 + 季度 + 核心战略}}

## 输入
- 产品：{{产品名 + 当前阶段}}
- 季度：{{Q1/Q2/Q3/Q4 + 起始日期}}
- 团队配置：{{N 个工程师 + 设计 + PM + QA}}
- 核心战略：{{本季度要实现的 1-3 个战略目标}}

## 路线图结构
### 1. 季度目标（3 个）
- 每个目标给：业务影响 + 度量指标 + 负责人
- 目标必须：可量化 + 有挑战但可达成 + 与战略对齐

### 2. 13 周时间轴
- 月度主题：每个月 1 个主题
- 关键里程碑：每月末有可交付物
- 周计划：按周分配功能 / 项目

### 3. 项目列表
对每个项目给：
- 项目名：{{简短}}
- 优先级：P0 / P1 / P2
- 负责团队：{{前端 / 后端 / 算法 / 跨团队}}
- 投入估算：{{人周}}
- 关联季度目标：{{对应哪个目标}}
- 关键依赖：{{依赖什么 / 何时可用}}
- 风险与缓解

### 4. 优先级排序
- 价值 / 投入比：每个项目评估
- 战略对齐：是否服务于本季度核心目标
- 依赖关系：A 必须先于 B 的，标注
- 风险评估：技术 / 业务 / 跨团队风险

### 5. 不做的
- 明确本季度不做的事
- 理由：避免范围蔓延
- 推迟到：下季度 / 下下季度

### 6. 沟通与同步
- 周会：每周同步进度
- 月度评审：每月评估季度目标进度
- 季度评审：季度末评估整体达成
- 调整机制：什么情况下调整路线图

## 写作硬规则
- **每个项目都有量化价值**：用户数 / 收入 / 留存 / 满意度
- 投入估算必须基于过往数据，不凭感觉
- 优先级评估有标准（不拍脑袋）
- 不做的明确列出，避免范围蔓延
- 季度目标 ≤3 个，太多等于没目标
- 调整机制提前约定，避免临时大改

## 自检
- [ ] 季度目标是否 ≤3 个
- [ ] 每个项目是否有量化价值
- [ ] 投入估算是否基于数据
- [ ] 不做的项目是否明确
- [ ] 调整机制是否清晰
