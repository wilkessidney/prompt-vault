## 访谈方案结构
### 1. 研究目标
- 核心问题：1-3 个，每个给：知道 vs 想知道 vs 怎么用
- 决策影响：研究结论会决定什么产品决策
- 不研究什么：明确边界

### 2. 招募
- 目标用户画像：角色 / 行为 / 痛点
- 招募数量：{{N 个（建议 5-8 个 / 用户分层）}}
- 招募渠道：{{社区 / 客户群 / 推荐 / 第三方}}
- 筛选标准：必选 + 不选
- 激励：金额 + 形式

### 3. 访谈提纲（≤45 分钟）
- 开场（5 分钟）：自我介绍 + 知情同意 + 不诱导承诺
- 暖场（5 分钟）：了解用户背景，不进入主题
- 主问题（25 分钟）：
  - 行为类：「上次你做 XX 是什么时候，过程如何」
  - 痛点类：「那个过程中最麻烦的是什么」
  - 方案类：「你试过什么方法解决，效果如何」
  - 价值类：「如果有个工具能 XX，你觉得值多少」
- 收尾（5 分钟）：有没有我漏掉的 + 推荐下一个受访者
- 致谢 + 激励

### 4. 主持技巧
- 不诱导：「你觉得 A 怎么样」（×）「A 和 B 你选哪个，为什么」（√）
- 不引导：「你会不会用 XX」（×）「你什么时候会用 XX」（√）
- 追问：「为什么」「能详细说吗」「能举个例子吗」「那时候你心里怎么想」
- 沉默：用户沉默时等 5 秒再说话

### 5. 记录与分析
- 录音 + 笔记双轨
- 访谈后 24 小时内整理关键洞察
- 横向对比：所有访谈的相似与差异
- 模式识别：3-5 条核心洞察 + 每个给 ≥3 个用户引用

## 写作硬规则
- **每个问题都要开放式**，不用「是不是」「会不会」
- **不出现产品名**，避免用户迎合
- 不诱导用户对方案表态（用户不知道自己真正想要什么）
- 提纲是参考，不是脚本——根据回答追问
- 知情同意必须明确录音 + 数据使用范围

## 自检
- [ ] 是否每个问题都是开放式的
- [ ] 是否避免了诱导性提问
- [ ] 招募标准是否清晰
- [ ] 访谈后是否有标准化分析流程
