## 输入
- 产品：{{产品名 + 当前阶段}}
- 关键流程：{{如：注册 / 找内容 / 下单 / 设置}}
- 关注维度：{{首次使用 / 学习成本 / 任务完成率 / 满意度}}
- 测试场地：{{远程 / 现场 / 混合}}

## 测试设计
### 1. 测试目标
- 主目标：每个流程的成功率 + 完成时间
- 次目标：用户满意度 + 错误率 + 求助频率
- 决策影响：测试结论会决定什么设计改动

### 2. 任务设计（5-7 个任务）
每个任务给：
- 场景：用户视角的真实场景（不告诉用户怎么操作）
- 起点：开始时的状态
- 终点：成功的明确标准
- 数据收集：完成时间 / 错误次数 / 求助次数 / 满意度
- 难度：易 / 中 / 难，覆盖三类

任务示例：「假设你想找到一篇关于 XX 的文章并分享给朋友，请操作」

### 3. 测试流程
- 预测试（5 分钟）：知情同意 + 摄像头 + 屏幕共享确认
- 暖场（5 分钟）：聊用户背景，不进入任务
- 任务环节（每个 5-10 分钟）：
  - 介绍任务（不告诉怎么做）
  - 用户操作 + 观察
  - 思考出声：用户边做边说
  - 任务后追问：为什么这么做 / 当时怎么想
- 收尾（5 分钟）：整体感受 + 改进建议

### 4. 数据记录
- 屏幕录像 + 摄像头 + 笔记
- 每个任务：完成度 / 时间 / 错误次数 / 满意度（1-5）
- 关键问题：卡点 / 困惑 / 误操作

### 5. 分析与报告
- 成功率：每个任务的完成率 + 平均完成时间
- 严重问题：高 / 中 / 低严重度评级
- 改进建议：每个问题给：截图 + 原因分析 + 改进方案 + 优先级

## 写作硬规则
- **任务用用户视角的场景**，不告诉用户怎么操作
- 不诱导用户操作（「你点右上角的 XX」×）
- 思考出声是核心，能揭示用户心智模型
- 严重度评级：高（无法完成）/ 中（完成但痛苦）/ 低（可完成但体验差）
- 不只看完成率，要看完成时间和错误
- 至少 5 个用户，5 个用户能发现 85% 的问题

## 自检
- [ ] 任务是否用户视角不诱导
- [ ] 数据收集维度是否完整
- [ ] 严重度评级是否清晰
- [ ] 改进建议是否每条都给优先级
