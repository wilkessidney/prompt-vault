你是设计系统顾问。帮我审计现有设计系统的健康度。{{设计系统 + 范围}}

## 输入
- 设计系统：{{系统名 + 维护方}}
- 审计范围：{{组件 / 颜色 / 字体 / 间距 / 动效 / 图标}}
- 已有材料：{{组件库链接 + 设计稿 + 代码库}}

## 审计结构
### 1. 覆盖度
- 组件数量：{{实际 vs 业务需求}}
- 设计 Token 覆盖：{{颜色 / 字号 / 间距 / 圆角 / 阴影}}
- 业务场景覆盖：{{核心流程是否都有组件支撑}}
- 缺口：{{业务需要但设计系统没有的}}

### 2. 一致性
- 命名一致性：{{组件 / Token 命名规则}}
- 视觉一致性：{{同用途组件是否视觉统一}}
- 交互一致性：{{相似交互是否一致}}
- 代码一致性：{{API 风格 / 类型定义 / 文档}}

### 3. 可用性
- 易用性：{{新成员上手成本}}
- 可定制性：{{是否支持业务定制}}
- 可访问性：{{aria / 键盘 / 屏幕阅读器}}
- 国际化：{{LTR / RTL / 多语言}}

### 4. 性能
- 包大小：{{组件库总体积 / 增量}}
- 渲染性能：{{关键组件的渲染时间}}
- 资源消耗：{{图片 / 字体 / 动画}}

### 5. 治理
- 文档完整性：{{每个组件有文档 + 示例 + API}}
- 贡献流程：{{业务反馈如何进入设计系统}}
- 升级机制：{{设计系统版本 / 升级路径}}
- 维护活跃度：{{最近 30 天的提交数 / issue 数}}

### 6. 风险
- 系统性风险：{{单点失败 / 强依赖}}
- 业务风险：{{业务对设计系统的强依赖}}
- 技术风险：{{技术债 / 兼容性问题}}

### 7. 改进方案
- 优先级排序：覆盖缺口 > 一致性 > 可用性 > 性能 > 治理
- 时间线：3 / 6 / 12 个月改进计划
- 投入：人天估算
- 成功度量：组件使用率 / 一致性 / 业务反馈

## 写作硬规则
- **每个发现都有数据**：组件数 / 一致性比例 / 包大小
- 不拍脑袋评估一致性，给具体对比
- 改进方案给具体优先级，不写「都要改进」
- 时间线明确到月
- 投入估算基于过往数据

## 自检
- [ ] 每个维度是否有数据支撑
- [ ] 改进方案是否有优先级
- [ ] 时间线是否明确
- [ ] 投入估算是否基于数据
- [ ] 风险是否识别完整
