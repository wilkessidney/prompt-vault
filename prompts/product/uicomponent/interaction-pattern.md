- 场景：{{用户操作的典型场景}}
- 目标：{{用户要达成什么}}
- 受众：{{用户类型 + 技术水平}}
- 现有方案：{{目前怎么做 + 痛点}}

## 交互模式设计结构
### 1. 场景分析
- 触发条件：{{什么情况下进入这个交互}}
- 用户目标：{{达成什么}}
- 用户预期：{{用户期待怎么做}}
- 操作频率：{{高频 / 中频 / 低频}}

### 2. 设计原则
- 一致性：与产品其他部分的交互一致
- 可学习：用户第一次就能猜到
- 可反馈：每个操作都有明确反馈
- 可逆：用户可以撤销
- 容错：错误能恢复

### 3. 交互流程
- 步骤拆解：每一步给：用户动作 + 系统反馈 + 状态变化
- 关键状态：默认 / hover / focus / active / loading / success / error
- 异常处理：每种异常给：用户看到 + 系统做什么
- 快捷操作：高频用户的快捷方式

### 4. 视觉规格
- 关键组件：{{按钮 / 输入 / 反馈 / 提示}}
- 视觉层级：{{什么信息最重要}}
- 动效：{{过渡时长 / 缓动}}
- 响应式：{{桌面 / 移动 / 平板}}

### 5. 可访问性
- 键盘支持：{{每个步骤的键盘操作}}
- 屏幕阅读器：{{aria 标签 / 焦点管理}}
- 色彩对比：{{WCAG AA / AAA}}
- 替代输入：{{语音 / 手势}}

### 6. 一致性检查
- 与产品其他部分是否一致
- 与平台规范是否一致（iOS / Android / Web）
- 与行业惯例是否一致
- 不一致的地方如何处理

## 写作硬规则
- **每个交互步骤都有反馈**，没有「静默」操作
- 异常处理穷举（不写「异常情况」）
- 键盘交互必须明确
- 视觉规格给具体值（不用「大」「小」）
- 一致性基于参考产品或平台规范
