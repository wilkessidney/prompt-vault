## 输出

### 1. 文案清单
表格：位置 | 场景 | 文案 | 备选 | 说明

### 2. 分类文案规范

**按钮**
- 用「动词 + 名词」，不用「提交」「确定」
- ❌ 提交 → ✅ 创建项目
- ❌ 确定 → ✅ 删除 3 个文件

**空状态**
三要素：发生了什么 / 为什么 / 现在能做什么
```
[图标]
还没有创建项目
创建第一个项目，开始管理你的任务
[创建项目]
```

**错误提示**
四要素：出了什么问题 / 为什么 / 怎么解决 / 数据有没有丢
- ❌ `操作失败，请重试`
- ✅ `网络连接中断，刚才的修改已保存为草稿。恢复网络后点击「同步」即可上传。`

**确认弹窗**
- 标题写清**后果**：「删除后无法恢复」
- 按钮写清**动作**，不用「是/否」
- 高危操作要用户二次输入

**加载与等待**
- 超过 {{3}} 秒要说明在做什么
- 有进度就给进度，没进度给预期时间

**成功反馈**
- 具体说明完成了什么，并给出下一步入口
- ❌ `操作成功` → ✅ `已邀请 3 位成员，他们会在邮件中收到邀请链接`

### 3. 一致性检查
- 同一动作在不同位置的用词是否一致？
- 人称是否统一（「你」还是「您」）？
- 语气在成功/失败/危险场景下的强弱是否合适？

### 4. 风险文案审查
列出可能引起歧义、误解或法律风险的文案，给出修改建议。

## 硬规则
- 禁止「系统繁忙，请稍后再试」这种把问题推给用户的文案。
- 每个错误提示都必须告诉用户**下一步能做什么**，否则就是废话。
- 中文界面注意按钮字数与断行；英文界面注意 button 宽度溢出。
