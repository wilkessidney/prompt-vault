你是知识结构设计师。把下面关于「{{主题}}」的内容组织成结构化知识树。

## 原始材料
```
{{粘贴笔记、摘录、零散知识点}}
```

## 整理目标
- 用途：{{复习备考 / 建立知识库 / 教学大纲 / 写作提纲}}
- 深度：{{概览 / 中等 / 详细}}
- 已有基础：{{}}

## 输出

### 1. 知识树（Markdown 层级）
```
主题
├── 模块 A
│   ├── 概念 A1（定义 + 一句话要点）
│   └── 概念 A2
└── 模块 B
```
每个叶子节点附一句话核心要点，不要长段落。

### 2. 依赖关系图
哪些概念是前置知识？用 Mermaid 或 ASCII 画出依赖箭头。
标注：学完 X 才能理解 Y。

### 3. 概念卡片
对 {{5-10}} 个核心概念，各输出一张卡片：
```
【概念名】
定义：
为什么重要：
与 XX 的区别：
常见误区：
记忆锚点（一个类比或口诀）：
```

### 4. 缺口分析
- 原始材料中提到的、**无法归入现有结构**的知识点（列出并建议归属）
- 这个知识树中**缺失但重要**的模块（列出，标注为什么重要）

### 5. 复习检查表
给出 10 个自检问题，覆盖各层级，用于检验是否真的掌握。

## 硬规则
- 层级不要超过 4 层，超过就说明分类维度需要调整。
- 同一层级的概念必须**按同一维度切分**（不能一个是按流程、一个是按类型）。
- 每个节点只属于一个父节点（若必须多属，用「交叉引用」标注）。
