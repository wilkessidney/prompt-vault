- 产品：{{产品名 + 用户量}}
- 当前反馈渠道：{{NPS / 客服 / 社区 / 销售 / 应用商店}}

## 反馈闭环结构
### 1. 反馈收集
- 主动收集：{{NPS 调研 / 满意度调研 / 用户访谈}}
- 被动收集：{{客服工单 / 应用商店评论 / 社区帖 / 销售线索}}
- 全渠道汇总：{{所有反馈进统一系统}}

### 2. 反馈分类与标签
- 维度：{{功能 / 性能 / UI / 价格 / 客服 / 稳定性}}
- 情感：{{正面 / 中性 / 负面}}
- 用户类型：{{新手 / 专家 / 决策者 / 执行者}}
- 优先级：{{紧急 / 高 / 中 / 低}}

### 3. 反馈分发
- 紧急反馈：{{24 小时内回应 + 责任人}}
- 高优先级：{{本周内处理 + 责任人}}
- 中优先级：{{本月内纳入 backlog}}
- 低优先级：{{季度评审}}
- 分发机制：{{基于问题类型自动分发}}

### 4. 反馈处理 SLA
- 紧急：24h 回应 + 72h 解决
- 高优先级：48h 回应 + 1 周解决
- 中优先级：1 周内纳入 backlog
- 低优先级：1 个月内处理

### 5. 反馈到产品的路径
- 反馈 → PM 评审：{{周会评审}}
- 评审 → 决策：{{纳入 backlog / 拒绝 / 推迟}}
- 决策 → 落地：{{排期 / 上线}}
- 上线 → 反馈者通知：{{告诉反馈者我们做了什么}}

### 6. 反馈闭环报告
- 月度反馈报告：{{数量 / 分类 / 处理率}}
- 季度趋势：{{反馈类型变化 + 满意度变化}}
- 产品改进溯源：{{X 项产品改进来自 Y 条反馈}}

### 7. 反馈者沟通
- 反馈收到确认：{{自动回复}}
- 处理进度通知：{{每周}}
- 处理结果通知：{{完成后主动告知}}
- 致谢：{{对高价值反馈者致谢}}

## 写作硬规则
- **每个反馈都有归属**：避免收上来没人管
- SLA 清晰可执行
- 反馈 → 产品的路径可追溯
- 反馈者必须被通知（哪怕拒绝）
- 月度报告公开，让团队看见

## 自检
- [ ] 反馈收集是否全渠道汇总
- [ ] 分类标签是否清晰
- [ ] SLA 是否明确可执行
- [ ] 反馈 → 产品路径是否可追溯
- [ ] 反馈者是否被通知
