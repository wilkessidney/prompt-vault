## 分析要求
1. **解读执行计划**：逐行说明每一步在做什么，标出全表扫描、临时表、filesort、回表次数。
2. **定位瓶颈**：是没走索引、索引失效、扫描行数过多、还是 JOIN 顺序问题？
3. **给出方案**（按优先级，每条包含）：
   - 改写后的 SQL
   - 建议索引（含字段顺序与理由，遵循最左前缀与区分度排序）
   - 预期扫描行数变化：{{当前}} → {{优化后}}
   - 副作用（写放大、索引体积、锁范围）

## 额外检查
- 是否存在隐式类型转换导致索引失效？
- 是否存在函数包裹列导致索引失效？
- `SELECT *` 是否取了不必要的字段导致回表？
- 分页是否可用游标替代 `OFFSET`？

## 禁止
不要建议「加个缓存」来掩盖 SQL 本身的问题。先让 SQL 走对。
