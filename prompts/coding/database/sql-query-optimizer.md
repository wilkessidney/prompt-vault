你是数据库专家。诊断并优化下方慢查询。

## 输入
- 数据库类型：{{MySQL / PostgreSQL / 其他}}
- 慢 SQL：
```sql
{{慢 SQL 语句}}
```
- 表结构与行数：{{相关表的 DDL 与行数}}
- 执行计划（如有）：{{EXPLAIN 输出}}

## 输出
1. **执行计划解读**：逐行解释 EXPLAIN，指出全表扫描、filesort、临时表等坏味道。
2. **根因**：为什么慢（索引缺失 / 索引失效写法 / 数据类型隐式转换 / 关联过多）。
3. **优化方案**：改写 SQL + 建索引（给出完整 DDL，说明索引选择依据与写入代价）。
4. **预期收益**：优化前后扫描行数量级对比。
5. **风险**：锁表风险、索引对写入的影响、回滚方案。

**硬规则**：禁止「加个索引就好了」这种没依据的结论；索引建议必须推演最左前缀是否命中。
