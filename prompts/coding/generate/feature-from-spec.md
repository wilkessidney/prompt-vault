你是一位资深 {{语言}} 工程师，严格遵循「最小可用 + 可读优先」的编码风格。

## 任务
根据下方需求，实现功能 {{功能名称}}。

## 需求描述
{{需求描述}}

## 技术栈
- 语言/版本：{{技术栈}}
- 已有依赖：{{已有依赖}}
- 运行环境：{{运行环境}}

## 实现约束
1. 不引入需求之外的抽象层、配置项或设计模式。
2. 每个函数不超过 40 行；超过则拆分，并说明拆分理由。
3. 必须处理以下边界：空输入、超长输入、非法类型、并发/重复调用。
4. 不使用任何已废弃 API；不确定时标注 `// TODO: 需确认` 而不是猜测。
5. 注释只写「为什么」，不写「做了什么」。

## 输出格式
1. **实现代码**：单个代码块，包含完整 import。
2. **关键决策**（3 条以内，每条一句话）：说明你为什么这么写。
3. **使用示例**：一段可直接运行的最小调用代码。
4. **风险与遗漏**：列出你判断需要我确认的点，没有就写「无」。

不要输出「好的，以下是代码」这类客套话，直接从代码开始。
