帮我在 {{候选A}} 和 {{候选B}}{{候选C（可选，没有则忽略）}} 之间做技术选型。

## 项目背景
- 项目类型：{{Web / 移动 / 数据 / AI 应用}}
- 团队现状：{{人数，已有技术栈，熟悉度}}
- 关键诉求（按优先级）：{{性能 / 生态 / 招人容易度 / 文档 / 长期维护}}
- 时间约束：{{上线时间}}

## 输出
### 1. 评分矩阵
维度 | 权重 | 候选A | 候选B（1-5 分 + 一句话依据）
维度至少含：学习曲线、生态成熟度、性能上限、招聘市场、社区活跃度、与现有栈契合度、踩坑资料丰富度。

### 2. 加权总分与结论
给出明确推荐 + 置信度（高/中/低）。

### 3. 反方观点
扮演最反对这个结论的人，说出他最强的 3 条理由。

### 4. 切换成本
如果 6 个月后要换到另一个，代价是什么？

**硬规则**：评分必须给依据，禁止裸打分。
