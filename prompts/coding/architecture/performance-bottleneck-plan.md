帮我生成 {{系统/页面/接口}} 的性能排查与优化方案。

## 现象
- 症状：{{慢在哪里：接口 P99 / 页面加载 / CPU / 内存}}
- 量化数据：{{具体数值，如 P99 从 200ms 涨到 3s}}
- 技术栈：{{技术栈}}
- 流量特征：{{QPS / 数据量}}

## 输出
### 1. 假设清单
按「可能性 × 验证成本」排序，列出至少 6 个瓶颈假设（含数据库慢查询、N+1、缓存未命中、锁竞争、GC、网络 RTT 等，按技术栈裁剪）。

### 2. 测量手段
每个假设对应一条可执行的验证命令或脚本（EXPLAIN、火焰图、链路追踪、日志聚合）。

### 3. 修复优先级
速赢（1天内）→ 中期（1周）→ 长期，各自预期收益估算。

### 4. 防回归
上线后用什么指标监控、设什么告警阈值。

**硬规则**：禁止未测量就给优化结论；每条修复必须绑定它对应的假设编号。
