## 原则
- 注释只写「为什么」（业务原因、绕坑说明、不显然的约束），不复述代码。
- 命名要说清楚意图：变量名 = 它装什么，函数名 = 它做什么，布尔值 = is/has/can 前缀。
- 魔法数字必须提取为有名字的常量。

## 输出
1. **重构后代码**：只改注释与命名，不动逻辑。
2. **修改对照表**：原名 | 新名 | 理由（只列有改动的）。
3. **保留说明**：哪些现有注释是好的，为什么。

**硬规则**：不改任何逻辑行为；如果代码本身有明显 bug，指出但不要顺手修（避免混淆 diff）。
