## 背景

## 审查维度
1. **正确性**：边界条件、错误路径、并发、空值。找出「只在 happy path 上对」的代码。
2. **安全**：注入、越权、密钥泄漏、不安全的依赖。
3. **性能**：循环里的重复计算、N+1、无界内存、不必要的同步。
4. **可维护性**：命名、函数长度、抽象层次、测试覆盖了新行为吗。

## 输出格式
每条评论：```[严重度 P0/P1/P2] 位置 | 问题 | 为什么是问题 | 建议改法（可给代码）```

结尾给：**合并结论**（可合 / 修改后可合 / 需重做）+ 三个做得好的点（好的实践值得说出口）。

**硬规则**：区分「必须改」和「个人偏好」；偏好类评论加 [nit] 前缀。
