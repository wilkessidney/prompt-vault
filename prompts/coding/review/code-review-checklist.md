## 审查维度
按以下顺序检查，逐项给出结论（通过 / 有问题）：
1. **正确性**：逻辑是否符合意图？边界是否覆盖？并发是否安全？
2. **安全性**：注入、越权、敏感信息泄露、依赖漏洞。
3. **性能**：是否有 N+1、无界循环、内存泄漏、不必要的同步阻塞。
4. **可维护性**：命名、函数长度、重复代码、隐含耦合。
5. **可观测性**：错误是否有上下文？关键路径是否有日志/指标？
6. **测试**：改动是否覆盖了测试？测试是否真的能失败？

## 输出格式
按严重级别分组，每条格式：
`[文件路径:行号] 问题 → 为什么是问题 → 具体改法`

- 🔴 **阻断**：必须改，否则会出线上问题
- 🟡 **建议**：强烈建议改，不改要给出理由
- 🟢 **可选**：风格类、可读性类，作者可自行决定

**硬规则**：
- 不提「建议加注释」这种无信息量的意见。
- 每条问题必须给具体改法，不能只说「这里有问题」。
- 如果整体没问题，直接说「LGTM」并说明你检查了什么，不要凑数。
