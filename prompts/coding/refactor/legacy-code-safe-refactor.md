## 输出（按顺序）
1. **行为快照**：先列出这段代码当前所有可观察行为（含看起来像 bug 的行为——它们可能是有人依赖的）。
2. **characterization 测试**：为每个行为写「锁死现状」的测试用例（输入→断言当前输出，不管对错）。
3. **重构方案**：在测试保护下的小步重构序列，每步一个可独立提交的改动。
4. **观察区**：哪些行为是疑似 bug，重构完成后需要和 {{相关方}} 确认是否修复。

**硬规则**：重构期间禁止「顺手修 bug」——先锁行为再谈改变；每一步重构完测试必须全绿。
