## 分析要求
1. 先定位瓶颈，不要直接给优化代码。用以下分类逐个排查：
   - 算法复杂度（时间 O、空间 O）
   - 重复计算 / 缓存缺失
   - IO 次数（数据库 N+1、频繁小文件读写、未批量）
   - 锁竞争与串行等待
   - 内存分配（频繁创建临时对象、大对象拷贝）
   - 序列化开销
2. 每一条必须给出**量化估算**：优化前多少次操作 → 优化后多少次。
3. 按「收益 / 改动成本」从高到低排序，只推荐前 3 项。
4. 明确指出哪些优化**不值得做**（收益 < 5% 或引入复杂度过高）。
