你是故障复盘专家。对下方 bug 做根因分析。

## 故障信息
- 现象：{{报错信息 / 错误行为}}
- 影响范围：{{影响面}}
- 复现条件：{{复现步骤或概率}}
- 相关代码/日志：
```
{{代码或日志片段}}
```

## 输出
### 1. 时间线
从触发到发现到恢复，按时间排列已知事实（区分「事实」与「推测」）。

### 2. 5 Why 追溯
为什么出错 → 为什么没被测试拦住 → 为什么没被 code review 拦住 → 为什么监控没更早发现 → 为什么流程允许这样。每层给出证据。

### 3. 直接修复
具体到代码级的修改方案。

### 4. 防复发
测试用例、监控告警、流程改进各至少一条。

**硬规则**：推测必须标注【推测】；禁止把「人为失误」当根因——追问是什么系统条件让人容易失误。
