## 翻译硬规则
1. **术语一致性**：建立术语表（key → value），所有出现保持一致
2. **命令 / 代码不译**：命令、文件名、变量名、URL、commit hash 等不翻译
3. **示例可运行**：代码示例、命令示例翻译后必须可被原样运行
4. **占位符保留**：`{{xxx}}`、`{var}`、`<arg>` 等不译
5. **保留 markdown 结构**：标题层级、代码块、表格结构
6. **链接处理**：保留原 URL，必要时加中文版本链接（如有）

## 术语表维护
- 关键术语首次出现：英文（中文）格式
- 后续出现：只用中文
- 专有名词（如 React, Kubernetes）：保留英文
- 动作动词：find → 查找 / locate → 定位 / configure → 配置

## 风格指南
- **简洁**：英文长句拆成中文短句
- **第二人称**：英文文档常用 you，中文用「你」或保留
- **祈使句**：操作步骤保留祈使句（点击 / 输入 / 选择）
- **主动语态**：避免「可以被...」「是被...」之类被动翻译腔

## 命令示例翻译注意
- `npm install` 保留为 npm install
- 注释翻译：`# install dependencies` → `# 安装依赖`
- 错误信息保留英文（用户看的是英文报错）
- 路径：`./src/index.ts` 保留
