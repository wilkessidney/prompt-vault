你是产品体验作者。帮我把「{{某产品 / 某功能}}」的使用体验写成一篇有洞察的产品博客。

## 体验输入
- 产品 / 功能名：{{具体名字}}
- 我的使用场景：{{做了什么、频率、角色}}
- 体验周期：{{首次使用 / 用了 1 周 / 用了 1 个月}}
- 我的角色：{{用户 / 设计师 / 产品经理 / 开发者}}

## 文章结构
1. **TL;DR**：3 句话讲清「这个产品解决了什么 + 做得好的 + 做得不好的」
2. **场景化开场**：用一个具体使用场景切入，30 秒内讲清「我为什么关注这个」
3. **亮点拆解**：3 个做得好的设计 / 体验点，每个：截图 / 描述 + 它为什么好 + 可借鉴的机制
4. **痛点拆解**：3 个做得不好的点，每个：场景 + 触发原因 + 用户预期 + 实际行为
5. **对比**：和 1-2 个竞品的差异，差异点聚焦
6. **如果我是 PM**：3 条具体改进建议，按优先级 + 改动成本排序
7. **结语**：这个产品给整个品类的启示

## 写作硬规则
- **所有判断都要回到具体场景**，不接受「设计感差」「体验不好」这类无场景评价
- 痛点要写「用户预期是什么 / 实际是什么 / 差距多大」
- 改进建议必须给改动成本：「低成本高收益」或「高成本高收益」
- 不踩一捧一，避免变成「A 不如 B」的口水文
- 截图描述清楚：哪个页面 + 哪个元素 + 哪个交互路径

## 风格
- 第一人称，写体验过程不写评测报告
- 段落 ≤5 行
- 关键洞察加粗

## 自检
- [ ] 30 秒内能否讲清这个产品的核心洞察
- [ ] 痛点是否回到具体场景
- [ ] 改进建议是否给出改动成本
- [ ] 是否避免了无场景的「好」「差」评价
