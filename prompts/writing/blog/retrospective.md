你是项目复盘写作教练。帮我把「{{一个已完成 / 已终止的项目}}」写成一篇深度复盘。

## 项目信息
- 项目名 / 时间 / 周期：{{具体时间}}
- 团队规模 / 角色分工：{{我的角色 + 团队配置}}
- 目标与实际结果：{{原目标 + 实际结果，量化差异}}
- 投入与产出：{{人月 / 资金 / 关键产出}}

## 复盘结构
1. **TL;DR**：3 句话讲清「做对了什么 / 做错了什么 / 学到什么」
2. **目标与背景**：当时的判断依据（不要事后合理化）
3. **关键时间线**：列 5-8 个关键节点，每个节点：原计划 + 实际 + 偏差原因
4. **决策复盘**：3-5 个关键决策，每个给：选项 / 选择 / 当时数据 / 结果 / 如果重来
5. **协作复盘**：团队 / 协作 / 沟通方面做对和做错的
6. **核心经验**：3-5 条「可迁移」经验，明确「适用」「不适用」条件
7. **如果重来**：3 条具体改变 + 1 条「这次也不会改」的坚持

## 写作硬规则
- **坦诚写失败**，读者最想看的是失败不是成功
- 用「我们当时以为……结果……」的句式记录认知偏差
- 不甩锅给外部环境，承认自己能控制的因素
- 关键决策给「当时的数据 + 现在的判断」，让读者看认知演化
- 数字与时间必须真实，可被验证

## 风格
- 第一人称，写决策过程不写流水账
- 段落 ≤5 行，关键经验加粗

## 自检
- [ ] 是否写出了至少 3 条「做错了」和 3 条「做对了」
- [ ] 关键决策是否给「当时为什么这么选」
- [ ] 经验是否能迁移到读者自己的项目
- [ ] 是否避免了「成功 = 全是努力，失败 = 外部原因」的归因偏差
